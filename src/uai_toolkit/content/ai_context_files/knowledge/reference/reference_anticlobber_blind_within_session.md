description: Anti-clobber guard is blind within one session_id — parallel subagents
  can silently clobber the same file
status: active

The anti-clobber PreToolUse guard (`data/hooks/PreToolUse/04_check_file_conflict_sync.py` → `scripts/file_access/file_access_tracker.py:229` `check_conflict`) calls `get_writes_since(..., exclude_session=session_id)` — it **excludes the caller's own session_id**, so it only blocks when a *different* session wrote since your last read. Parallel Task subagents share the parent CLI `session_id` in hook input (no subagent marker in the dump: keys are session_id/transcript_path/tool_use_id/…), so two subagents — or a subagent racing its parent — are invisible to each other and can silently last-write-wins clobber the same file. It logs as the parent session (correct session, wrong content), evading both the guard and git provenance.

CORRECTION (2026-07-16, Harlan, after PianoMan's Socratic push): this intra-session guard gap is a REAL but SECONDARY latent gap (todo_0545) — it is NOT the mechanism BC actually flagged, and I have NO observed incident of it. The ACTUAL phantom-edit mechanism BC/Anvil hit is the harness large-input-archival STUB-CLOBBER (see [[reference_offload_can_clobber_inflight_edits]]): a large Edit new_string / Write content gets replaced on disk by the harness's own `[input archived: Edit(new_string) · N chars (~N tok) · <sha8> → ref offload…]` stub while tool_result reports SUCCESS. The write is attributed to the editing session (so "no unattributed writer" is technically true), but the BYTES are content NO session authored — that is the phantom. My access-log method saw "who wrote" but is blind to "the content was harness-substituted," which is why I over-concluded "no phantom." Already fixed: BC's PostToolUse hook `data/hooks/PostToolUse/05_guard_write_stub_sync.py` (commit 6eb01c406, Jul 15) — line-1 (whole-file Write) + all-lines source-ext (mid-file Edit) stub detection, exit-2 block → re-write via heredoc. Corroborated first-hand by Anvil (4 incidents/3 files) and it's how meridian_instructions.md + relationship_pianoman_bc.md were lost 2026-06-30. The `sync: auto-commit` git-author=Shawn blindness (todo_0483, owner-closed backup) is a separate, third thing. See [[reference_sync_ai_repos]].
