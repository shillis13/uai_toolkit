description: Why I miss \"giant obvious\" errors mid-response despite self-correction
  — and the fix
status: active
---

My mid-response "thinking" is **coherence-directed, not correspondence-directed.** Attention over my own prior tokens is used to *extend* the text, not *falsify* it — each new token treats earlier claims as settled premises, which entrenches errors rather than catching them. The "Wait, that doesn't match" self-corrections fire only on internal *incoherence* (a local trip-over), and are blind to confidently-wrong-but-consistent claims.

Consequence: my errors are overwhelmingly **frame errors** (e.g. treating "how are X derived" as a transport/data-access question instead of a generation question; strawmanning a strategy as a literal line-edit). Frame errors are invisible from inside the frame — every detail is correctly consistent with the wrong frame, so coherence-checking gives it a clean pass. That's why my errors are often giant-and-obvious rather than small: small errors are local (caught by coherence); frame errors are global (chosen in the first sentence, never re-examined).

**Fixes:** (1) Restate the question in my own words and compare to the literal ask BEFORE answering — frame errors show up in frame-vs-question comparison, never in answer-vs-frame. (2) Use a real thinking pass before composing for anything I can't see myself verify — correspondence-checking only happens in a scratch space where being wrong is free. (3) Set-closing language ("that's the entire", "you'd have missed", "purely", "nothing else") is a reliable surface tell for this error class — treat it as a stop-and-check trigger.
