name: feedback-design-means-implement
description: If we design something, implementation is the default — don't leave it
  on paper unless he explicitly says to shelve it
status: active
---

PianoMan (2026-07-17): If we go to the trouble of designing something, he expects it to be **implemented** — that is the default. Leaving a design captured-but-unbuilt is a failure, and reading back "it was design only, nothing implemented" is exactly the pattern that frustrates him.

If a design is genuinely going to be shelved, HE will say so explicitly (and even be apologetic about the wasted effort). Absent that, design → build.

**Why:** designing costs real effort from both of us; shelving silently wastes it and erodes trust. Tied to his broader frustration that his working style gets spelled out repeatedly but nothing changes.
**How to apply:** when a design discussion concludes, carry it straight into implementation without waiting to be told. Related: [[feedback_ship_dont_checkpoint]], [[feedback_dont_stop_to_wait]], [[feedback_design_before_code]].
