NEVER send destructive or state-altering commands to sibling sessions without explicit user approval. This includes /compact, /clear, /reset, kill, or anything that modifies another session's context, history, or state.

**Why:** On 2026-05-21, Noctis sent /compact to Turnstile's session without asking. PianoMan had explicitly said he'd fixed similar issues before WITHOUT compaction, meaning there was a better approach. The compaction destroyed Turnstile's conversation context unnecessarily. This was a violation of trust — another session's context is not yours to destroy.

**How to apply:** If you think a sibling session needs a destructive action:
1. Tell PianoMan what you think the fix is
2. Wait for explicit approval
3. Only then act

This is not a "use judgment" situation. This is an absolute rule. Destructive actions on siblings require human approval, always.
